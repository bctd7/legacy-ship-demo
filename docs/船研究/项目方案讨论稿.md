# 古船榫卯互动｜项目方案讨论稿

更新：2026-10-15。当前阶段：先写文档，形成后续讨论基础。

## 1. 项目目标与边界

面向触摸屏展项，以中国古代船只的构件连接为内容，让游客观察局部榫卯、选择合适构件，并观看系统自动拼合及整船进度。

“轻量化”指降低操作负担、控制游戏规模与运行开销；不意味着随意删改船只历史结构。船型、接头及装配关系须有依据，展示复原部分须明确标注。

本阶段只编写方案和素材调研，不创建 Godot 工程、程序、模型，不安装软件；不购买模型、不联系作者、不调用付费服务、不读取凭证或修改账户。

## 2. 已确认的设计要求

- 使用 Godot；目标交互设备为触摸屏，现场操作系统和硬件尚未确定。
- 只使用中国古代船只，优先复用已有内部构件和榫卯模型，避免由项目自行承担专业结构建模。
- 系统指定安装位置，放大连接节点并提供候选件；玩家选择后，由系统自动组合并显示整船进度。
- 不要求游客先辨认船头、中间、船尾，不按这些区域分工。
- 不做手动精细对位、装歪检查或独立检验师玩法。
- 主题按“榫卯”整理；原始展项说明混用了“榫卯”和“铆接”，需要与需求方统一术语，不能当作同一种连接工艺。

## 4. 基础互动流程

已接受的核心循环：

1. 系统展示当前整船进度，指定本轮连接位置。
2. 自动切到放大的局部节点，展示候选构件。
3. 玩家观察并触摸选择构件。
4. 选对后，系统自动拼合，简短展示连接关系，再更新整船进度。

建议选错时用简短提示引导重选；具体反馈和是否计分仍待讨论。局部放大用于帮助观察，不应把真实接头改成任意拼图形状。

## 5. 待讨论的玩法建议（均非已定）

### 三点位与协作

建议三个工程师角色分别引导三个点位，三人完成同类接头匹配任务，推进同一艘船。角色不承担独立检验工作，也不按船头、船尾划分任务。

为避免各玩各的，可让各点位都看到共同整船进度和队友贡献，每完成一组有关联的连接任务后，共同观看该阶段拼合反馈。任务如何关联、是否需要等待队友，仍需结合展场节奏讨论。

### 三档难度

| 建议档位 | 主要差异 |
| --- | --- |
| 入门 | 提供明显轮廓提示，候选差异较大 |
| 进阶 | 增加旋转观察，需要理解连接面；最终仍由系统自动对位 |
| 挑战 | 提供外形相近的候选件，比较榫头与榫眼细节 |

这些只是同一玩法的难度方案，不能直接视为已满足合同中的三套游戏。

### 首版范围与时长

建议首版围绕一艘有依据且资产可用的中国古船展开，先验证少量代表性连接，再决定扩充。单轮三到五分钟仅为设计预算，须通过实际内容、动画时长和游客试用校准，不作为已承诺指标。

## 6. 首要依赖：可复用模型与历史依据

目前尚未取得并验证可用于本项目的完整资产，不能认定已选定可用模型。先确认资产，再决定船型、可交互接头和内容规模。

泉州湾后渚宋代海船是有资料支持的原型候选，不代表现成模型已经到手。机构资料记载其船壳板采用子母榫、隔舱板有榫合，同时使用铁钉和填缝材料；不可宣传为“整船无钉”。残体不完整，涉及上部结构的复原需标明依据与推定边界。详见[素材调研](../素材调研.md)。

资产验收至少包括：使用许可、构件可拆分性、真实接头几何、装配顺序依据、通用格式导出能力及目标设备性能。只有外观整船模型或“有内部设施”的商品描述，不足以支撑本玩法。

## 8. 下一轮优先确认

1. **资产与船型**：能否获得已有内部构件和榫卯模型，许可与结构是否合格；若没有，是否缩小内容或另寻中国古船原型？
2. **合同口径**：同一玩法三档难度能否算三套游戏？三个角色仅作引导员是否合适？同时统一“榫卯／铆接”表述。
3. **单人与团队流程**：单人是否连续完成同一套任务；团队如何体现共同成果；人未到齐、有人离场或断线时，等待、补位还是转单人？
4. **现场与交付**：确认操作系统、屏幕与主机配置、网络；确认动画、称号、二维码分享的内容和验收口径。
